# 수집 누락과 소속 판정 보완

2026-11-05 소스 수정 기록입니다. 기존 배포판의 실측 결과와 구분합니다.

- cgroup v1과 v2의 전체 항목을 확인합니다. 같은 Pod에 대해 서로 다른 경로가 나타나면 첫 항목을 임의로 선택하지 않고 충돌을 기록합니다. v2 루트 경로와 유효한 v1 Pod 경로가 함께 있는 환경은 허용합니다.
- 경로에 서로 다른 컨테이너 ID가 여러 개 있으면 마지막 ID를 임의로 선택하지 않습니다. 같은 ID의 반복은 허용하고 대소문자를 정규화합니다.
- cgroup을 읽기 전후로 프로세스 시작 시간을 비교해, 읽는 동안 PID가 재사용된 경우를 거부합니다. 이는 단일 시점의 원자적 수집을 보장하지 않습니다.
- 상위 cgroup.procs 읽기에 실패해도 읽을 수 있는 하위 cgroup을 계속 확인합니다. 잘못된 PID 항목 하나 때문에 같은 목록의 다른 유효한 프로세스를 버리지 않습니다. 오류는 남겨서 최종 결과가 완전 수집으로 표시되지 않도록 합니다.
- vendor 의존성 파일을 기존 Cargo 체크섬에 맞게 복원했습니다. 의존성 버전이나 알고리즘은 변경하지 않았습니다. Git 줄바꿈 변환을 vendor에서 제외하고 빌드 스크립트에 전체 vendor 체크섬 검사를 추가했습니다.

프로세스 정지 방식, 정지 시간 제한, 메모리 예산, ELF core와 manifest 형식은 유지합니다. 애플리케이션 TLS의 평문은 덤프 시점의 사용자 메모리에 실제로 남아 있고 해당 범위가 수집된 경우에만 분석할 수 있습니다. 이번 수정이 TLS 전체 복호화나 과거 통신 전체 보존을 제공하는 것은 아닙니다.

Linux x86-64 musl 환경에서 자동 검사 66개가 통과했습니다. 새 검사는 cgroup 항목 순서와 충돌, 중첩 컨테이너 ID, 식별 중 PID 재사용, 부모 읽기 실패 후 자식 탐색, 잘못된 PID 이후 유효 항목 처리를 다룹니다. 기존 정지, 메모리 범위, 파일 게시와 자원 예산 회귀 검사도 포함합니다. 환경변수가 필요한 기존 실노드 검사는 설정하지 않았으며, 이 수정본으로 실제 Kubernetes Pod를 새로 수집한 검증은 아직 수행하지 않았습니다.

빌드 스크립트는 release 프로필 테스트 후 정적 Linux 실행파일을 만들고 소스 해시와 실행파일 해시를 검사합니다. 새 실행파일과 manifest는 release/review-20261105에 배치합니다. 이전 release/poddump는 기존 검증 기록과 함께 유지합니다. 복원된 vendor 파일 중 의존성 자체의 ignore 규칙에 걸리는 파일도 배포 소스에 포함해야 하며, 전체 체크섬 검사가 누락을 검출합니다.
